# dsh 论文检索与纸面配对试运行包 v1.3

交付日期：2026-10-21。基于作者提供的 v1.2 修改；本包初始零论文，真实 dsh 检索尚未运行。改动与已做验证见 [CHANGELOG.md](CHANGELOG.md)。

## 你的理解与本次边界

“一个异质压力 → 六项条件/单篇卡 → 两三个问题簇 → 主体与改法/八步配对卡 → 现有标准工作流”主线正确，补充：

- 检索、读卡和分簇可以交替，问题簇按失效链和接口收束，不是等读完再机械分组。
- 缺证据记 HOLD；oral、核心代码和专业认可分别核验，不用一个总分互相抵消。
- 第四步只得到纸面配对候选。真实触发、独立增量、统一框架的严格退化关系和最终效用，由后续强推理模型及标准工作流判断。

v1.2 只做到单篇卡。本次按作者最新请求，扩展到有界初步配对；不把旧包“不配对”的指令沿用为现行范围。

## 客户端如何开始

1. 把交付 zip 解压到当前工作区根目录。顶层应出现 dsh_literature_pipeline/，不要再套一层同名目录。遇到同名旧包先保留旧目录，避免覆盖已有记录。
2. dsh 客户端选择**这个工作区根目录**。当前仓库里包已经放好，可直接使用。
3. 在一个主会话粘贴：

~~~text
读取当前工作区 dsh_literature_pipeline/START_HERE.md，
按 v1.3 的冻结配置完成一次有界并行试运行。
使用客户端已有模型、检索和文件工具；先核对实际能力。
本轮做到论文证据卡、问题簇和初步配对卡，然后停止并交接。
~~~

不需要你使用命令行。Python 校验由 agent 通过客户端已有执行工具调用。没有执行工具或 Python 时照实交“未发布草稿”，不能声称校验入池成功；不安装环境、不改客户端设置。

## 已选好的首轮范围

唯一压力：**客户端标签分布偏斜**；同构、同步；只讨论实际观测支持内的优化/个性化失配。三个 Finder 检索线索不等于三个已验证问题簇。

首轮最多 12 个去重候选、6 篇定向深入、6 对粗筛、2 张详细配对卡；最多 3 个活动子任务，不递归派单。最多 24 条 query、60 次远端取页，45 分钟计划止损。[设计] 到点停止新任务并收尾；提示词不是强制进程超时器。约 40 篇/15 个想法是后续软目标，本轮不自动扩池。

默认分波使用原生 subagent：发现三路并行 → 去重 → 读卡最多三路 → 新子任务校核最多三路 → 纸面配对 → 总控发布。沿用“批量处理、单一写索引”优点，减少每篇多次交接与可选 workflow DSL 依赖。若只有 workflow 工具，也可按当前工具 schema 实现同样的分波；不得假设旧 JS 示例仍适配。

## 文件和产物

- [START_HERE.md](START_HERE.md)：唤醒入口。
- [prompts/00_orchestrator.md](prompts/00_orchestrator.md)：总控；其它 prompts 是子任务工作单，不是新的研究角色规则。
- [configs/search_plan.json](configs/search_plan.json)：范围和配额。
- templates/：单篇和配对 JSON 模板。
- tools/pool.py：本地结构校验、导出和报告，Python 标准库。
- tests/：离线合成夹具，不是论文、检索结果或科学实验。

真实产物写 runs/<run_id>/：staging 保存发现/去重/请求日志；inbox 保存各子任务独占草稿；records 保存单篇事实；pairs 保存纸面配对；exports 保存可读卡片和后续入口。只有总控写 records、pairs、exports。PDF 下载到该轮 local/，不要放原 paper/、refs/、master's thesis/ 或自动扫描它们。

所有正式单篇卡的 ACCEPTED 仅指纸面入池。所有配对统一 scientific_status=UNQUALIFIED、training_authorized=false。零合格配对可以完整交付，不以不足数量为由改压力、凑论文或续额度。
