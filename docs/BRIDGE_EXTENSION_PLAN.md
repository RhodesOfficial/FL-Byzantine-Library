# FLGo 桥接层基础设施开发计划

范围：只建设可供多种聚合器复用的六项能力。保持现有七个聚合器的构造、调用和结果契约；实验专属配置及新聚合器注册不在本计划内。

## 依赖与并行安排

- 主线：**1 任务数据预隔离 → 2 根数据加载 → 3 运行时上下文传递**。第 2 项需要第 1 项产生的任务元信息；第 3 项可先独立实现，但端到端验证需第 2 项完成。
- **4 缓存键管理**可与主线并行；**5 状态保存与恢复**依赖第 4 项确定实例身份及重建时机。
- **6 统计读取与日志**可与 1—5 并行。完成主线后再做根类聚合器的联合验证。

## 1. 任务数据预隔离

- **改动目标：**在客户端划分训练样本之前，预留可信服务端样本，并保存可复现的来源与索引；避免与客户端训练样本重叠。
- **改动文件：**`data_loader.py`（复用或补充现有拆分辅助函数）；任务生成处，例如 `flgo_byzantine/toy_benchmark/core.py`；任务目录中的根数据元信息。
- **改动要点：**固定种子；记录原训练池、根集和客户端分区的索引关系；任务生成后不再从已分给客户端的样本里临时抽取根集。不要修改 easyFL 的通用分区器。
- **验证方式：**用现有 toy 任务生成一份小任务，检查根索引与所有客户端索引交集为空；相同种子重新生成得到相同索引。

## 2. 按需加载根数据

- **改动目标：**让需要可信数据的聚合器取得与当前 FLGo 任务同源、同预处理方式的数据集；普通聚合器不加载它。
- **改动文件：**新增 `flgo_byzantine/root_data.py`；`flgo_byzantine/algorithm.py` 的 `Server.initialize()` 及聚合器构造路径。
- **改动要点：**从任务元信息和对应任务管道读取根样本，校验索引有效且非空；仅在被选聚合器声明需要根数据时加载，并在服务端复用同一数据集。`data_loader.py` 的 `get_dataset()` 属库内另一入口，不能直接替代 FLGo 任务管道。
- **验证方式：**用测试接线让现有 `fl_trust.py` 在最小 toy 任务上读取根集并完成一次聚合；同时运行 `avg`，确认其启动路径没有触发根数据加载。

## 3. 传递运行时模型与任务计算器

- **改动目标：**让需要服务端模型、设备及任务损失计算的聚合器取得当前轮上下文。
- **改动文件：**`flgo_byzantine/algorithm.py` 的 `Server.aggregate()` 及需要上下文的构造／调用接线。
- **改动要点：**传递当前 `self.model`、`self.device`、`self.calculator`；每轮更新模型引用，不把初始模型固定在缓存实例中。保持 `instance(updates) -> Tensor[D]` 的旧调用路径可用；明确模型参数向量与返回更新的符号约定。
- **验证方式：**在 toy 任务上用现有 `fl_trust.py` 连跑两轮，检查它使用第二轮模型；再跑 `avg` 对照现有 FLGo 桥接测试，检查结果未变化。

## 4. 管理有状态实例的缓存键

- **改动目标：**只在构造所依赖的固定上下文改变时重建实例，保留正常跨轮状态。
- **改动文件：**`flgo_byzantine/algorithm.py` 的 `Server.aggregate()` 中实例键与创建逻辑。
- **改动要点：**为需额外上下文的实例加入稳定配置／根数据标识；仅对构造固定响应人数的类纳入 `n`。轮号和模型权重不入键；现有七类沿用原有键规则，尤其保留 `cc` 的中心。
- **验证方式：**用已注册的 `cc` 连跑多轮并改变实际响应人数，检查实例与中心未因人数变化而重置；`krum` 在人数变化时仍重建。

## 5. 保存与恢复聚合器状态

- **改动目标：**使 checkpoint 续跑保留有状态聚合器的历史，而非只恢复全局模型。
- **改动文件：**`flgo_byzantine/algorithm.py` 的 `Server.save_checkpoint()`、`Server.load_checkpoint()` 及实例创建处。
- **改动要点：**保存实例身份和可序列化状态；加载时先恢复待应用状态，实例按键构造后再注入；旧 checkpoint 缺少该字段时仍可读取。不要把根数据副本写进 checkpoint。
- **验证方式：**使用已注册的 `cc` 比较连续运行与中途保存后续跑的模型和聚合器中心；再读取一份不含新字段的旧格式 checkpoint。

## 6. 统一读取聚合器统计

- **改动目标：**让已有聚合器的运行统计进入桥接日志，同时保持没有统计的聚合器可用。
- **改动文件：**`flgo_byzantine/algorithm.py` 的聚合后统计收集；`run_flgo_byzantine.py` 的 `ByzantineLogger.log_once()`。
- **改动要点：**仅在实例提供 `get_attack_stats()` 且返回可记录的映射时读取；处理空值、数值转换及键冲突；日志仍能序列化为 JSON。
- **验证方式：**用测试接线运行现有 `fl_defender.py` 或 `foundation.py`，检查其统计写入记录；再运行 `avg`，检查原有日志字段仍在且无需新增统计。
