3.4 . Details of the proposed method
Algorithm 1 illustrates the overall training process of the proposed 
method, which consists of five main phases: system initialization, local 
model update, malicious gradient detection for online clients, malicious 
gradient detection and correction for delayed clients, and global model 
update. The technical details of each phase will be elaborated in the 
following subsections.
3.4.1 . System initialization
The server randomly initializes the global model, which includes con­
figurations such as the model structure, learning rate, and number of 
training rounds, and then distributes the initial model parameters to all 
clients.

3.4.4 . Malicious gradient detection and correction for delayed clients
In asynchronous FL, the server may receive not only current gradi­
ents but also delayed gradients in each round of training. These delayed 
gradients may include malicious gradients sent by Byzantine clients, as 
well as conflicting gradients from benign clients that deviate from the 
current update direction. A straightforward approach would be to use 
MD to directly tackle these issues. However, based on the properties of 
MD described in 
Section 3.4.3, MD can only identify malicious gradients 
with significant anomalies in their numerical distribution; it cannot de­
tect conflicting gradients that have a normal numerical distribution but 
deviate in their update direction. Therefore, we propose a malicious gra­
dient detection and correction method by combining MD with projection 
correction, as shown in 
Algorithm 4, which mainly consists of two steps: 
first, MD is employed to detect obvious malicious gradients, yielding the 
initially filtered set of benign delayed gradients; second, projection cor­
rection is applied to the conflicting gradients in the delayed gradients 
that deviate from the current update direction.

5.1.2 . Attack settings
Six attack scenarios are considered in this paper, two for data poi­
soning attacks and four for model poisoning attacks, which are as 
follows:
1. Backdoor (BD) attack [ 40]: BD attack is a targeted data poison­
ing attack. The attacker injects a predefined trigger into part of 
its local training samples and changes their labels to an attacker-
specified target class. For CIFAR-100 and COVIDx, the trigger 
is implemented as a fixed patch pattern attached to the input 
images; for Shakespeare, the trigger is implemented as a fixed 
token/character pattern inserted into the input sequence.
2. Label flipping (LF) attack [23]: LF attack is a data poisoning at­
tack. We convert the source label 𝑠 of its local sample to the target 
label 𝑙−𝑠− 1 , where 𝑙 is the total number of labels in the dataset.
3. Gaussian (GS) attack [22]: GS attack is a model poisoning attack. 
We replace the raw gradient with random noise sampled from a 
zero-mean Gaussian distribution (with the standard deviation of 
the noise set to 200).
4. Model replacement (MR) attack [41]: The backdoor trigger of MR 
attack is set up as for backdoor model poisoning attack. Following 
the work [ 41], in order to mitigate the dilution of the attack 
effect due to global aggregation, we extend the poisoning local 
gradients by setting the weight factor 𝛾=𝑛  and send the extended 
local gradients to the server, where 𝑛 is the total number of clients.
5. LIE attack [42]: LIE attack is a typical colluding model poisoning 
attack. The attacker manipulates all malicious clients to provide 
a range of perturbations. The attacker uses the maximum value

5.1.3 . Parameter settings
Our evaluation is conducted on an AMD EPYC 7453 CPU, 64 GB 
DDR4 memory, and an RTX 4090 GPU with 48 GB VRAM, operating on 
Ubuntu 20.04 with PyTorch and Python 3.9.
The Non-IID setting of FL is simulated using the Dirichlet distribu­
tion, denoted as 𝐷𝑖𝑟(𝑛, 𝛽), where 𝑛 is the number of clients and 𝛽 controls 
the degree of Non-IIDness in the dataset. A smaller 𝛽 corresponds to a 
higher degree of Non-IIDness. Among all clients, delayed clients account 
for a proportion 𝛿. To simulate a more realistic delay environment, we 
use the Pareto distribution 𝑃 𝑎𝑟𝑒𝑡𝑜(𝑥𝑚 = 3, 𝛼= 1.5) . This distribution 
models a scenario where the majority of clients have low delays, while 
a small number of clients experience significantly higher delays. In our 
experiment, the majority of clients’ delays are concentrated between 3 
and 10 rounds, while the delays of a few clients reach 15 or even higher. 
This setting aligns with typical FL scenarios, where most clients have fast 
or moderate network conditions, but a small subset of clients may expe­
rience large delays due to factors such as network instability or resource 
constraints.
