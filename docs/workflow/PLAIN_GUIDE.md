## 1. 一句话讲课题

联邦学习里，有些类别的样本很少（尾类），而且持有尾类数据的设备往往更慢、经常不能按时上交。已有方法（CReFF）只用"按时交上来的设备"来估计每个类别长什么样，于是**慢设备上的尾类知识被系统性地漏掉了**。FedPCC 想把这部分偏差纠正回来，提升尾类的识别率。

## 2. 用一个比喻

老师要统计全班对某道题的平均理解程度，但只收"按时交作业的同学"的答卷。如果按时交作业的同学恰好都是理解得好的，那么统计出来的平均值就偏高了。这就是**来源偏差**。

FedPCC 的做法：
1. **估计每个同学按时交作业的概率**（模块 A1：完成概率估计）。根据历史上"邀请了几次、按时完成了几次"来算。
2. **用"上次的答卷 + 按概率放大的本次修正"来补全没交的人**（模块 A2：类条件缓存校正）。交得少的同学一旦交上来，他的修正量会被放大，这样在平均意义上就不偏了。统计学里这叫逆概率加权。
3. **用补全后的"每类平均情况"重新训练模型最后一层（分类头）**（模块 A3：受约束的均衡分类器校准）。做法是生成一些合成特征，让它们产生的梯度和补全后的梯度对得上，再用这些特征训练分类头。

## 3. 三道关（论文能不能成立，看这三个问题）

| 关口 | 白话问题 | 如果失败意味着什么 |
|---|---|---|
| 第一关 G1 | 来源偏差真的存在吗？慢设备上的尾类数据，和快设备上的同类数据真的不一样吗？ | 偏差不存在，就没有需要纠正的问题，A 的主创新不成立 |
| 第二关 G2 | 实际中用估计出来的概率（而不是上帝视角的真实概率），能把偏差估准吗？ | 只有真实概率才有效，说明方法落不了地 |
| 第三关 G3 | 估准了之后，尾类识别率真的提高了吗？头类损失了多少？ | 估得准但没用，方法没有实际价值 |

还有一个**探针 P**：模型前面提取特征的部分（骨干）固定不动时，这些特征本身能不能把尾类区分开？如果特征本身就分不开，后面怎么调分类头都没用。P 就是提前检查这件事。

## 5. 术语表

| 术语 | 白话 |
|---|---|
| 客户端 / 端 | 参与联邦学习的一台设备，本项目主设置是 20 个 |
| 长尾，IF=100 | 样本最多的类别是最少类别的 100 倍 |
| α=0.1（Dirichlet） | 控制各客户端数据分布有多不均匀；0.1 表示非常不均匀，很多客户端只有少数几类 |
| 头类 / 尾类 | 样本多的类别 / 样本少的类别 |
| 骨干（backbone） | 模型前面提取特征的部分 |
| 分类头（head） | 模型最后一层，把特征变成"属于哪一类"的打分 |
| 冻结参考 | 固定下来、不再训练的模型快照，用来做测量 |
| 类梯度 g_ic | 第 i 个客户端第 c 类数据，告诉分类头"该往哪个方向调" |
| G_c | 把所有客户端的第 c 类梯度按样本数加权汇总，代表"第 c 类整体的情况" |
| 完成概率 p | 某个客户端被邀请后按时交回结果的概率 |
| recall（召回率） | 某一类的样本里，被模型认对的比例 |
| smoke | 小规模冒烟测试，只验证"能跑通、算得对"，不能证明科研结论 |
| ε_num | 数值误差容差：两种算法算同一个量时，允许的浮点误差有多大 |
| W01–W07 | 研究合同里登记的各项工作量和成本。W02 是"测量类梯度要花多少计算和流量" |
| 预登记 / 冻结 | 先把计划和判据写死再跑实验，防止事后挑对自己有利的结果 |
| 配对种子 | 用同一组随机种子分别跑新方法和对照方法，公平比较 |
| 线性探针 | 固定骨干，只训练一个最简单的线性分类器，检查特征里有没有信息 |
