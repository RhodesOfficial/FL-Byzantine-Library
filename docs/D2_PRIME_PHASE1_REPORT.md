## 3. 停止原因：现有RFA没有实际逐端权重输出契约

用户明确要求：“RFA必须能输出真实逐端贡献权重”；接口缺失时“停下报告”，不得均匀兜底或换方法。因此本轮不自行修RFA，也不新增外部补算路径绕过前置验收。

源码证据：

- [RFA调用入口](<E:/Federated Machine Learning/FL-Byzantine-Library-astra/aggregators/rfa.py:49>)只返回聚合向量z，没有按输入顺序输出最终归一化权重，也没有`last_client_weights`或贡献trace属性。
- [Weiszfeld迭代](<E:/Federated Machine Learning/FL-Byzantine-Library-astra/aggregators/rfa.py:9>)使用`beta_i=alpha_i/max(distance_i,nu)`计算z，保存的是各迭代累计、拆分成两组的未归一化beta历史。组拆分的b在类中硬编码为5，没有绑定本轮真实恶意身份；这个分组只用于统计，不参与z的更新。
- [统计接口](<E:/Federated Machine Learning/FL-Byzantine-Library-astra/aggregators/rfa.py:57>)只返回两组跨迭代beta均值；[同步桥接](<E:/Federated Machine Learning/FL-Byzantine-Library-astra/flgo_byzantine/algorithm.py:87>)仅保留标量统计，未建立最终实际权重与`received_clients`的对应记录。
- 现有[D1桥接](<E:/Federated Machine Learning/FL-Byzantine-Library-astra/flgo_byzantine/d1_full_algorithm.py:217>)存在权重属性缺失时用`1/n`兜底的逻辑。它不是本轮RFA接线，且不能借用该兜底满足本关要求。混合聚合器的RFA“保留全部客户端”接口也不是实际贡献权重。

**边界：并非RFA数学上无法逐端归因，也不是所有内部权重信息丢失。**在有效迭代及输入顺序已知时，可以从最后一次真实beta归一化得到真实权重；这些内部记录可供后续精确接口修复使用。当前缺少经过独立重构验收、按客户端身份输出的接口，本轮没有将内部历史均值当作真实贡献。

固定张量原始证据已写入清单：CPU/float64，输入`[1]`、`[3]`，T=1、nu=1e-6、初始z=0。独立标量手算：

`beta=(1/2,1/6)`，总和`2/3`，实际最终权重`(3/4,1/4)`，故聚合结果`(3/4)*1+(1/4)*3=1.5`。

实际RFA返回`[1.5]`，与手算一致；均匀权重会给出`[2.0]`，不相等。实际属性检查：`last_client_weights=False`、`last_contribution_trace=False`；原始分组beta为`malicious=[0.5,0.16666666666666666]`、`benign=[]`，统计接口只给出均值`0.3333333333333333`及`0`。分组名称不代表此固定输入的真实身份。

该检查证明现有聚合可以产生非均匀实际贡献，均匀兜底错误；没有用被测函数生成预期权重或预期聚合值。
