修订不是给旧修正加更小系数，而是替换修正对象：

\[
v_C=H+\sum_j f_j\bar u_j,\qquad
v_R=H+\sum_j\pi_j\bar u_j,\qquad
z=\sum_j(\pi_j-f_j)\bar u_j.
\]

这里 \(H\) 是全体旧缓存均值，\(\pi_j\) 是总体组占比，\(f_j\) 是返回组占比，\(u_i\) 是解码后的缓存新增变化。准确缓存没有新增变化时，修正为零。组内交换性给出条件无偏性；它不保证均方误差总下降，也不保证自然异步返回满足条件。[文件：修订论证 §2–4]；[推断]

## 3. 关键结果及其含义

每个单元六端、二维、三个返回端，枚举全部 20 个不同返回集合；24 单元共 480 个独立初始化的反事实缓冲、1,440 条正式有效返回。代表单元的 20 个缓冲只计算一次并复用。评价为同一当前全端目标的平方误差，没有训练种子、置信区间或尾类准确率。[文件：PROTOCOL、manifest、summary]

### 3.1 新增变化分层有独立作用，但作用有条件

`heterogeneous_cache / fresh` 两种编码均得到：

|对照|全 20 集合的平均平方误差|
|---|---:|
|C，无分组缓存校准|0.025|
|R，总体占比 × 新增变化|0.0125|
|ABS，相同分组的绝对状态分层|0.02421875|
|CACHE，接收后全端缓存均值|0.0375|
|MSG，按差分消息分组|0.025|
|ID，连续 ID 固定分层|0.0326388889|

来源：[代表单元](../../../artifacts/direction_b/r01_v1/cells/heterogeneous_cache__top1__fresh.json)、对应 dense 单元；表末位四舍五入。[文件]

18 个集合有所有组返回，R 在这些集合误差为零；两个纯 A/纯 B 集合缺组，回退 C，误差各为 0.125。因此报告全体均值 0.0125，不能只报生效子集的零误差。七个对照共用同一状态和返回，不为 R 单独增加初始化信息。[文件]

ABS 在齐次缓存族与 R 相同，在异幅缓存族落后：它重新抽样了已完整知道的旧缓存差异；R 精确使用 \(H\)，只估计新增变化。这个对照支持差分处理的独立作用，而非只证明普通分层有用。MSG 的可达历史使所有最近差分都为 `(0.125,0)`，它只有一组并退化为 C；这只证明这个接口反例，不证明任意消息分组必败。[文件：原始单元、PROTOCOL]；[推断]

### 3.2 有非零压缩误差时仍可有益，但没有消掉压缩或年龄误差

`mixed_increment / fresh / Top1`：C 为 0.0328125，R 为 0.0203125，ABS 为 0.03203125；U 为 0.00703125。R 通过主判据，但仍落后于取消本次压缩的诊断。[文件：对应单元]

同族 Top1 改为 aged，R 为 0.046875，U 为 0.02177734375。U 保留相同源版本，不能称它为当前无损真值。`common_increment / fresh / Top1` 中所有端丢掉同一坐标，C 与 R 都是 0.0625，U 为零；分组没有信息能补回该共同压缩偏差。[文件：对应单元]；[推断]

本轮暖缓存历史恰能准确重建，因而**未检验历史压缩误差导致的分组错误**。U 只取消本次消息压缩，不能替代“无损历史重新分组”的诊断。年龄/残差门控控制是明确注入元数据的单元检查，不是长期缓存轨迹证据。上述缺口留在下一阶段条件验证中，不因当前主判据通过而消失。[文件：PROTOCOL、qualify.py]；[推断]

这些向量由夹具逐消息指定，初始化只验证消息状态可达；它们没有从同一个固定损失的确定性 \(d_i(s)\) 轨迹生成。同源版本下不同初始化消息也不能解释成该确定性梯度的重复精确求值。因此 aged 的“B 端半幅变化”只是一种事先指定的旧/新向量差输入；真实优化过程中源版本、梯度变化和返回顺序的联合一致性没有验证。[文件：PROTOCOL 的输入表、qualify.py]；[推断]

### 3.3 必须留下的负结果

1. **相似缓存不保证新增变化适合分层。** `unrelated_increment / fresh` 的 C 为 0.05，R 为 0.0652777778；aged 的 C 为 0.0326388889，R 为 0.0423611111。恒等和 Top1 均如此。即使枚举返回具有对称性，组内变化方差也能使 R 更差；条件无偏不等于低均方误差。[文件：四个 unrelated 单元]；[推断]
2. **每组有人不保证组内代表性。** 固定偏向 B 中大增量端的反控制中，真实全端新增均值为零，C 误差约 \(1/9\)，R 误差 \(1/4\)。可靠缓存和完整组覆盖均不能排除这个错误。[文件：controls.json，within_group_selection_bias]；[推断]
3. **R 不能支配所有合理直接对照。** unrelated 族中纯 CACHE 甚至优于 C、R；这说明先验缓存准确程度和变化结构影响最佳估计，不能删掉 CACHE 来维持贡献。[文件：全矩阵]；[推断]
4. **原暖缓存失败被修复，冷启动收益没有被继承。** 原四端准确缓存控制的 R 恰等于 `(0.5,0.5)`；冷未知缓存按规定回退。旧冷正例与本轮冷回退的适用范围不同，不能把两者收益相加。[文件：controls.json]；[推断]

## 5. 状态、协议与费用是否可信

### 5.1 验证到的工程范围

程序从真实编码帧解码增量，客户端与服务器依据同一解码值维护状态；最近消息由两步可达历史生成，未直接伪造。六个中断快照依次在准备后提交前、服务器提交后 ACK 前、ACK 已发送客户端未落盘、客户端确认后、所有贡献完成消费前、消费后。[文件：qualify.py，controls.json]

本轮只有序列化模型和一个实际解释器退出/重启；没有运行真实分布式网络，也没有注入文件写到一半、断电或并发服务器故障。`os.replace` 的保存读回与这些逻辑边界，不能证明生产系统事务耐久性。错误基准被拒收、同内容重复包不重复贡献、重复消费幂等，均在所测小状态范围内成立。[文件]；[推断]
