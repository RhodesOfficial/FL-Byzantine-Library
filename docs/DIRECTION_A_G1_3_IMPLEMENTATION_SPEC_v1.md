## 扫描、拒绝和副本
- label_mapping直接字段定位；完整items遍历及list副本前reserve一次扫描。
- 类集合完整遍历一次；每个类的sources完整遍历及list副本各一次，人工两类共3次。

- 已读字节复用给语法编译/人工执行；Python隐式导入I/O、物理I/O保持null。
- 输入/单次JSON/RPC上限64 KiB；最多64账项，三份编译对象和raw/JSON/string/UTF8/base64副本统一留64 MiB代理。
- 人工集合是字面小对象；不加载torch/CUDA。Windows外层及两个子进程轮询峰≤2 GiB，CPU代理≤256 MiB。

## 冻结计划
- A旧风险占额80秒/读写各3145728 B/192扫描，只结转一次；不是实耗或历史合规上界。
- 本单round1/round2各15秒/读写各393216 B/24扫描，seal合计10秒/各262144 B/16扫描。
- 每轮静态包络：读≤196608 B、写≤131072 B、扫描≤21；封存读写各≤196608 B、扫描≤16。
- 轮内手算：PS语法2文件读，Python语法3文件读，label 1，嵌套拒绝已通过类1，嵌套成功3，fixture读1，第二进程标记1，共12扫描。
- 封存：checkpoint读1；缓存5源码+plan+fixture+checkpoint+selfchecks哈希9；末端ledger/receipt哈希2、三个文件独立读3，共15扫描；若实际失败failure多1哈希，共16。
- 两轮、重复及失败均累加；同轮语法→CPU→第二进程→封存计一次工程，独立封存另计。
- 外层在启动解释器前设累计时间/阶段时间及峰限制，超限Kill(true)终止进程树；尾耗单独留10秒。
- 末端JSON字节数固定点收敛后一次性预留三次写/三次独立读/两次哈希，再写最终账本和回执。
- 最后三文件写完再独立读回，逐字节比较，并解析ledger/receipt与最终used逐项比较；只有通过才输出成功。
- manifest登记其余证据/源码哈希，末端ledger/receipt哈希独立字段，manifest自身排除以免循环。
- 运行时间包含启动、RPC、检查、封存；末端2秒为显式保护的占额上界，不作为精确实耗。
