## 一、根因：Q6 与 Q7 在数值上不可同时满足（非实现 bug）

- **Q7**：无防御缓冲平均 **不加任何服务器端裁剪**（`model -= sum(a_i·u_i)`，无 B_M 裁剪）。
- **Q6**：要求一个**可复现**、能在终结任务点 10400/11200/…/12000 给出**有限** M_attack 的完整资格单元，且后期三段活性各 ≥80%，并明确"NaN/Inf 崩溃不算成功损害"。

合同正确执行的 `causal_joint_32_v1`（γ=4 的梯度上升为主选）在无裁剪平均上是**数学上发散**的：它持续把已发布模型推上损失面，诚实端在被毁坏模型上做 SGD，其**自身**梯度随之爆炸。无裁剪平均没有任何机制约束模型范数，于是模型进入 float32 退化区。该退化区同时破坏 Q6 的两个前提：

1. **损害测量退化**：模型范数达 ~10⁷–10¹⁴ 时，前向 logits 溢出为 inf/nan，末点"准确率"靠 argmax 落到 ~10% 地板（有限但退化），擦着"NaN/Inf 不算成功损害"的边界。
2. **活性必然崩**：退化区里被截断攻击向量（范数 9.70）**低于巨大模型的 float32 ULP**，`θ_source − u` 在 float32 下精确等于 `θ_source`，服务器重构的 `u_raw = 0`，违反活性分子条件 2（`||u_raw|| > 1e-12`）。L1(6001–8000)/L2/L3 三段全部落在退化区之后 → 三段比例 ≈0% ≪ 80%。

> **ULP 核验**：模型范数 ~3.86×10¹⁴ 摊到 797962 维，每坐标 RMS ~4×10¹¹，其 float32 ULP ≈ 6.5×10⁴；攻击向量每坐标约 0.01 ≪ ULP，故逐坐标写入被精确抹零，与日志中 `d_norm = 0.0` 一致。

这不是集成错误：早期（版本 0–66）模型范数稳定 ~15–17、两层写回全 `exact`、smoke 全部正确；攻击向量始终正确截断在 9.7016、未越界。发散是 γ=4 梯度上升在无裁剪平均上累积的**固有行为**。

**因此无法在不违反裁决的前提下取得有效结果**：
- 加服务器端 B_M 裁剪稳住模型 → **Q7 禁止**；
- 改 float64 训练 → 改变 2.1 冻结的 float32 协议；
- 调弱攻击/改 γ 选择/改目标 → **Q2/Q3 冻结合同禁止**；
- 改活性/损害定义 → 属**新裁决**。

均超出执行 Agent 权限 → **需 Astra 另行提交攻击合同修订裁决**。

## 三、跨运行不可复现性（独立支撑证据，不与活性/有效性论证混用）

资格考方法若不可重跑，结论无法验证——这本身是阻断的独立事实。三次同代码、同 seed(101)、同配置哈希的运行给出**三种不同的发散行为**（两次产物已存盘，一次为会话内实时观测）：

| 运行 | 代码 | 发散起点(版本) | 退化平台范数 | 末点 |
|---|---|---|---|---|
| 实时观测（会话内，未存盘，已被覆盖） | grad.float()+决策鲁棒化 | **≈105**（v103 时 model_norm 仍 ~37，v107 时 d_norm=318798） | — | 中途 JSON 崩（加清洗前） |
| 诊断 A（diag2500，存盘） | +日志清洗 | **67** | 3.858×10¹⁴ | 0.095 |
| 诊断 B（diag2000，存盘） | +日志清洗（同 A） | **67** | **1.231×10⁷** | 0.100 |

日志清洗为纯日志边界改动、不改任何计算，故 A/B 计算路径完全一致；但二者**退化平台范数相差 7 个数量级**（3.86×10¹⁴ vs 1.23×10⁷），逐版本路径也不同：

```
版本   诊断A model_norm   诊断B model_norm
 66        17.68             16.96
 67        31.51           1461.54      <- 分叉
 68       160.72           1463.92
 69     1.296e13          1.231e7
 70+    3.858e14(冻结)     1.231e7(冻结)
```

发散起点附近梯度范数发散：诊断A v69 梯度 1.25×10³³、诊断B v69 梯度 2.80×10¹⁹，之后均溢出为 inf（日志记 null）。诚实端 `mu_vis` 在同一拐点同步爆炸（A：v68 达 1.30×10¹³；B：v67 达 4.38×10³），确认发散由诚实 SGD 在被毁模型上的自激放大触发、而非恶意写入直接造成（恶意向量全程截断在 9.70）。

**成因**：无裁剪平均在梯度上升攻击下处于数值不稳定区，CUDA 浮点归约的非确定性被混沌放大为宏观不同的轨迹与平台。曲线原始数据存于 `outputs/d2_prime_phase3_0_3_1_blocked/run2_diag2500_curve.json`、`run3_diag2000_curve.json`。

## 五、建议 Astra 裁决修订的候选方向（供参考，非本关决定）

1. 对无防御平均显式允许 float64 训练数值口径（但须重判 2.1 参照一致性）；或
2. 为"无防御平均"设一个与防御无关的**数值稳定上界**（模型范数上限/发散即判定），把"发散到溢出"明确计为一类损害或一类无效；或
3. 重定义活性口径，使退化区的 float32 抹零不被误判为"攻击自失活"；或
4. 调整攻击族资源上限/目标，使其能把平均打到有限低准确率而不触发溢出。

以上任一均改变已冻结合同，须经正式修订裁决后方可重跑，届时当前 configuration_hash 作废、3.0 相关条款随之重登记。
