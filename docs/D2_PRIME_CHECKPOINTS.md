## 二、所有执行会话共用的规则

### 统一交付与状态

每关保存独立的检查点记录，建议目录为 `outputs/d2_prime/gates/<编号>/<尝试号>/`，至少包含：

- `manifest.json`：代码/配置/任务/数据用途/种子/轨迹哈希，输入检查点的具体版本，实际运行单元。
- `report.md`：逐条判据、实测值或状态、证据路径、结论和唯一的下一步编号。
- `decision.json`：`gate_id`、`attempt`、`status`、`failed_criteria`、`next_gate`、`invalidated_gates`。
- 支撑判断的原始日志、异常用例和汇总；数值检查失败必须保存当次输入，不能只留错误数值。

状态只用：**PASS、FAIL、INCONCLUSIVE、BLOCKED、INVALIDATED**。完成运行不等于PASS；缺证据用INCONCLUSIVE，缺外部材料用BLOCKED；合法的负结果用FAIL。发现实现或数据错误才可作废受影响结果，不能因方法输给基线而作废。

任何门槛未通过，依赖它的训练不得启动；独立的文献核对、数据整理和实现验证可以继续。一次会话可以连续通过几关，但必须分别交付，不能只报告“阶段完成”。

### 比较口径与预注册阈值

下面的阈值是**本次拟定的研究决策规则，不是文献结论或鲁棒性定理**。0.1先登记；不得看到D2′输赢后降低门槛。

| 项目 | 固定口径 |
|---|---|
| 主指标 `M` | 十类宏准确率的固定末五点评估均值。同步对应D已有评估点；异步按同等任务进度取五点，不按聚合版本或挑最好一轮。终点单独报告。 |
| 异步评价横轴 | 以实际执行过训练且已终结的任务数对齐，拒绝/过期/丢失的已训练任务计入。12,000任务时末五点为10,400/10,800/11,200/11,600/12,000；达到上限停止新训练，待在途任务按原有效期终结后取得末点。记录同时的累计样本数/minibatch数与模拟时间。 |
| 开发与确认 | 101/102可用于开发；D1已用过的101–103不得称为确认种子。4.1登记4个未用于本方案选择的确认种子，确认批次不再调参。 |
| 数据用途 | 0.1固定开发评价集、攻击优化数据与最终评价集的用途和重叠检查。D1中已经查看过的数据不能改名为“从未使用过的测试集”；种子确认与数据留出分别披露。最终评价标签不得进入攻击搜索或防御参数选择。 |
| 可测攻击损害 | 无防御平均聚合的干净−攻击 `M` 跨开发seed均值≥5 pp，且每个seed均>0；终点下降方向也应一致。该条件不要求攻击必须打坏D2′。 |
| 比较地板 | `M <= 100/C + 5 pp` 视作该指标地板区，C为类别数；不能凭此判定所有算法都不可学。 |
| 干净性能容忍 | D2′相对同场景中较好的平均/稳健基线，平均`M`下降不超过2 pp；每个开发seed下降不超过3 pp。 |
| 开发阶段主要收益 | 在预先指定的联合攻击场景，D2′相对同预算强对照平均`M`提高≥2 pp，两个开发seed差值均>0。这是继续投入门，不是统计显著性结论。 |
| 慢端保留 | 对调度前固定的良性慢/快端分别计算 `r_G = sum(a_i) / sum(eta_M*h_i/K)`，分母包含已执行但被拒绝/过期的任务；`h_i`以首次合法到达时版本差计算，未到达者以到期时计算。再取相对保留 `R_slow = r_slow/r_fast`，干净时要求≥0.80。这样统一缩步长不会被误判为专门排斥慢端；绝对的`r_slow/r_fast`两项仍须分别报告。`r_fast=0`或群组无样本则指标不可判，不能当作通过。只作诊断，不向算法泄露身份真值；按身份和陈旧度同时分组。 |
| 持续停滞 | 将完整任务进度分为5个等长段；干净场景后4段中，任一段实际模型系数总量/对应无筛选名义总量<0.10，或整个段模型无有效位移而基线仍在学习，判为推进失败。若上传向量本身已趋零，须用贡献重构和基线对照区分收敛与门控停滞。 |
| 数值正确性 | CPU/float64合成检查逐元素`atol=1e-10, rtol=1e-8`；离散状态必须完全一致。真实模型贡献沿用F的“写回前分解＋独立写回舍入”两层核验，不能用放宽总误差掩盖漏项。 |

异步同任务数并不自动等于同训练计算量。若配对方法累计minibatch/处理样本数差异超过5%，效率结论必须再按相同实际工作量对齐；未对齐前只允许声称“同任务预算”的结果。不能为了让不同防御拥有相同到达序列而重放由另一方法产生的客户端更新；配对的是外生可用性/延迟随机源与资源规则，各方法客户端必须在自己的源模型上训练。

### 修正与结果复用

- **工程FAIL：**定位并修复，重跑本关及受影响下游；不通过性能调参修复任务号、快照或账本错误。
- **机制FAIL：**先做一次有明确假设的诊断修订，登记改动和失效范围，再完整重跑相关配对单元；同类问题第二次仍失败，进入停止/换向决策，不无限调门槛。
- **确认失败：**不得边查看确认seed边调算法。修订后原确认数据转为开发证据，重新登记确认批次；若资源不足，结论为尚未确认。
- **历史抵扣：**只有任务、配置、实现语义、指标、种子和配对证据都匹配时才能抵扣。旧模型平均与新差值平均数学等价，不自动构成数值轨迹等价。
- **缩小结论：**可减少适用条件或附加主张，不能取消“存在相对强对照的正面增量”。只有限流有效、只有弱攻击有效但没有对照增量、或只有单个好seed，不构成D2′通过。
