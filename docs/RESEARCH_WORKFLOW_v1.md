# 非攻击研究通用工作流 v1

日期：2026-10-20。面向以后新方向；由作者本次授权建立。旧 A 的冻结结论、已发生的费用和运行授权不由本文件追溯改写。

## 1. 入口、约束和职责

新方向先读本文件、`docs/RESEARCH_REUSE_CATALOG_v1.md`、`docs/MASTERS_THESIS_BENCHMARK_v1.md`，再按需读文献基座。不要默认继承 `docs/workflow/` 的 A 专用待办、D 编号、四项计次和历史资源特例。

导师不参与选题、机制或中途指导；论文完成后才判断是否够参加盲审。研究范围与资格以 `master's thesis/` 的具体论文为对照。Reviewer 承担技术判断，作者决定方向与资源，不把任何中途任务转为等待导师意见。[作者确认：2026-10-20]

|角色|负责|不应转嫁的事|
|---|---|---|
|作者|给出毕业时间、可用算力/费用、可投入工作日；选择方向与范围；理解并能解释最终论文。|不替 agent 调试、裁决公式或设计统计门槛；导师不作为中途支持资源。|
|Reviewer|必要条件检查、论文尺度对照、实验定义、独立审查、控制投入与范围；给具体下一单。|不能只审本单格式而忽略已知的全局反证；不能用越来越复杂的验收替代科学问题。|
|Executor|实现、适当验证、按协议实验、恢复、原始结果与成本记录；主动指出冲突与更便宜的验证办法。|不能改结果门槛、删失败样本、根据分数重抽；也不应在明显无科学价值的任务上沉默续做。|

默认串行写仓库，通过提交与文件交接；本文件不要求创建额外 agent。用户已经授权的范围内，正常只读、实现修复和计划内验证自主进行；权限、范围或总预算真正需要变化时才交作者。

## 2. 只有六步，不为每个工具新增研究关口

|步骤|最小产出|先决定什么|
|---|---|---|
|A. 明确问题|一页问题/目标/假设、最接近文献、硕士论文对照、复用清单。|是否真有需要解决的失配；目标是否可识别。|
|B. 必要条件与最小反例|解析条件、退化情形、一个正对照和一个零效应/失效对照。|恒等式是否已经否定目标；压力生成器是否实际起作用。|
|C. 探索性资格试验|有限候选及停止规则、代表工作周期成本、表征/状态/统计资格。|哪一条范围值得进入确认；允许探索但完整保留尝试。|
|D. 冻结确认协议|目标、数据/参考、主比较、成功定义、重复单位、预算与恢复方式。|什么证据足以支持或否定主张；什么属于新研究版本。|
|E. 方法与决定性对照|最短因果链实验、关键消融、成本和失败边界。|实际算法是否有效，诊断 oracle 是否被误当方法；收益是否来自额外预算。|
|F. 证据封版与写作|主张—证据表、本地硕士论文对照、局限、复现入口和成果去向。|可写的结论是什么；缺口是否关键；继续、收窄还是停止。|

有足够必要条件反证时可以从任意步骤直接停止当前主张，不必等下游工具通过。阶段可以合并交付；一份简单任务能回答的问题不拆成数轮文档审批。

**机制先有可触发范围，再谈条件收益。** 在纸面论证或同一代表周期中，列出新增模块的覆盖/容量/支持/秩等必要条件，并记录真实输入中的触发、回退和退化情形。例如全组覆盖要求组数不超过缓冲不同端数；这只是必要条件。一个早期缓冲关闭不代表整个动态路径都会关闭，提前停止应有足够反证或事前规则，不能事后挑结果。不要以人工正例、接口正确或全程回退“不劣于基线”替代独立增量。该检查并入现有任务，不新增研究关口。[经验来源：RESEARCH_FAILURE_LESSONS_v1.md]

## 3. 探索与确认分开，避免冻结错误设定

探索阶段先登记问题、有限候选范围、评价用途和总投入，再比较候选或诊断求解充分性；所有探索记录保留。看到结果后改变设计，明确记为探索性修订，不追认旧确认实验。

确认阶段在读主要结果前冻结范围和判据。记录已接触过哪些验证数据，测试集不用于选择机制、阈值或参考。更换总体、完成机制、目标权重、参考或成功标准，建立新版本，解释旧证据哪些仍可用。没有变化的基础对象只核对身份与必要不变量，不整包重验。

“求解没有收敛”“没有观测到效应”“必要条件不成立”“管线尚未跑完”是四种情况。报告和裁决必须区分；不能把其中一个补写成另外一个。

## 4. 每份任务必须有决策价值

任务单开头写：**本次工作回答什么；结果的哪一种取值会改变下一步。** 如果任何可能结果都无法改变已有结论，Reviewer 不派该单。

任务默认包含一个完整工程周期：实现、相关小型测试、必要修复、正式运行或诊断、保存与读回。首次通过即交付，不为消耗次数重复测试。语法检查、普通编辑、保存和同周期封存不分别建立审批关口。

**条件任务链的衔接（2026-10-21，作者重开 B 时明确）：** 当作者授权一个方向按阶段推进时，项目协议应在运行前写明后续任务、阶段通过/停止条件和整包资源边界。Reviewer 接纳当前阶段后，应在同一次交接中给出下一张完整任务单及 READY 条件；不能把“本单完成”写成“方向结束”或“没有后续授权”而断开已批准的推进链。科学主判据失败则停止对应主张，不借余额换参数续救。该条不自动扩大其他任务的授权；超出既定范围或投入仍按作者约束处理。研究交接不等于自动创建或发送其他会话。

任务结束分别记录：

|栏位|允许结论|含义|
|---|---|---|
|科学主张|支持 / 否定 / 未检验 / 证据不足|只按该主张的证据判断。|
|测量有效性|有效 / 无效 / 待补|数据身份、分母、随机单位、数值与协议是否可靠。|
|工程状态|完成 / 可修 / 停止|程序是否完成及修复是否仍值得做。|
|资源状态|限内 / 超限 / 部分未知|已知实际、估计、上界、预留分别列；未知不能写零或自动写超限。|

如果还需要 PASS/FAIL，总结必须带类别，例如“测量待补，科学未检验”，不写没有解释的总 FAIL。本规则仅用于未来任务，不改 A 的历史判定词。

## 5. 资源计划：先测代表周期，再一次性冻结总包

### 5.1 首次估计

先做一个代表周期，覆盖必要读取/初始化、主要计算、评价、保存和一次可恢复路径。分别记录冷启动与稳定工作量；只有研究对象本身包含冷启动时才把它混入每轮系统模型，不使用一个端的暂态最大值无意改变所有任务的时间尺度。

采用可解释的计划式：

$$
T_{\rm plan}=T_{\rm init}+N_{\rm planned}T_{\rm unit}
 +T_{\rm evaluation}+T_{\rm save}+T_{\rm repair\ reserve}.
$$

各项写明实测、外推或暂估，使用有限余量，保留一个完整恢复周期。只有有数据支持时才把估计称为上界。首次测量不足可暂停依赖工作并补一次有界测量，不要求先完成所有历史费用证明才能测量。

### 5.2 日常任务只保留必要资源字段

- 时间：计划总上限、实际累计、恢复/重复成本；人工工作日与程序秒数分开。
- 内存：按实际量具记录 GPU allocated/reserved、进程工作集或 Windows Job 值；对象不同不能替换名称。未覆盖的完整峰值标未知。
- 文件：新增/保存产物大小及预计余量。普通文档和 Git 读取不要求逐字节、逐扫描精确计费。
- 科学工作量：训练步数、模型/参考/种子、评价次数；只记录与成本或重复性有关的项目。
- 若论文声称通信效率：额外区分上行、下行、编码索引、协议元数据与重传；模拟逻辑字节不能冒称实际网络字节。

明确的物理资源和费用总限仍是硬限；使用简单、可核验的超时/容量检查，预计完成不了剩余最小工作时不启动。除非研究主张依赖它，不开发逐运算计费、无遗漏 I/O 证明、自定义解码器或跨进程封存体系。需要这些额外工程时，必须先说明为何普通实现不足及其论文价值。

### 5.3 只有一个累计账

每个运行有唯一身份和自身增量；恢复继承已完成对象和累计费用。准备阶段先跨轮累计，再与正式阶段相加一次；不要将各阶段“已含历史”的总计再次相加。风险预留不是实耗，旧未知不补造，已完成结果不因恢复而重训。

时间、内存和磁盘必须同时覆盖完整周期后再派单；不先批一小段，再因保存、复验或计量自身逐次追加。发现低估时，Reviewer 更新完整剩余计划并一次交代差额，不能连续以新增子任务绕过总上限。

## 6. 修复与止损：有限自主，不无限续单

以下是新任务的默认规则，可在启动前依据任务规模明确调整；不能在看到不利科学结果后悄悄放宽。

1. **无新增科学结果的工程错误**，在固定科学协议和总预算内由 Executor 修复。默认一个周期容纳首次运行及至多两次修复后的验证，不把每次编辑、语法检查各记一个新额度。
2. **同一根因连续两次修复后仍未消除**，停止该实现，提交根因与更简单替代方案。不同错误虽不满足同根因条件，仍共享同一总预算与工作日上限。
3. **已产生新科学结果后出现异常**，先保留完整/部分/未开始清单。允许事前定义、身份可验证的恢复；会重抽、重训已完成对象、改优化状态或改结果含义的恢复，先由 Reviewer 定义边界。不得因低分重跑。
4. **默认一个工作项最多两次交付审查往返。** 第三次前必须先复核研究价值和任务拆分，决定合并、简化、明确缺项或终止。这个复核通常由 Reviewer 自主完成，不自动新增作者审批。
5. **默认连续五个工作日没有新的科学信息或决定性资格证据**，暂停新增实现，做一页范围审查。工程、资源、数学文档跨类别累计，换文件或错误签名不重置。
6. 科学必要条件失败立即停止当前主张。只有新范围有独立依据、作者选择新投入，才立新版本；旧失败保留。

“五个工作日”“两轮交付”是本次采用的过程止损尺度，不是文献定理，也不是强迫每个实验五日内成功。长运行可以在启动前声明等待期与信息节点；不能事后把无进展解释成预定长任务。

## 7. 数值验证与实现验证要匹配结论

优先使用手算反例、成熟数值库、标量参照、容差与少量关键不变量。只有误差可能翻转主结论，才升级到区间计算或更高精度。若已证明目标恒为零且通过条件要求正下界，不先做完整误差传播工程。

只测试真正可能错的边界：数据分母、空类、参考身份、完整/部分/未开始、重复消息、恢复基准。模型/协议变更重验受影响部分；不因文档更新重跑实验，不为了扩大检查数量反复验证已通过且未变的实现。

## 8. 文件与分支组织

每个新方向使用 `docs/projects/<方向ID>/`：

- `STATE.md`：一页当前目标、四栏状态、已接触数据、下一个决定与资源余量。
- `PROTOCOL.md`：当前生效的科学定义和预算，旧版本按提交定位。
- `TO_EXECUTOR.md` / `TO_REVIEWER.md`：任务与交付；历史由 Git 留存。
- `DECISIONS.md`：追加关键科学结论、范围或总预算变更。一段即可解释的修复不另建裁决 vN。

主线默认从 `master` 的已接纳基础建立，不复制 A 的整套工作流目录。复用旧成果按目录索引和固定提交取用；共同代码进入 `master` 不代表其科学效果通过，也不使旧实验自动适用于新方向。

作者直接指令优先于旧角色文件。普通实现选择与既有授权无需反复请示；换方向、实质收窄目标、增加总投入或不可逆外部操作按实际授权处理。本工作流不自动授权提交之外的远程推送。

### 8.1 每个方向结束时，经验必须分两处去向

无论成功、科学停止、资源停止或主动收窄，都在同一次结束交接中留下可引用复盘及去向表；不只把 STATE 改成 CLOSED，也不为“写经验”另派实验或多轮审查。简单方向可在已有 DECISIONS/复盘中完成，不强制新增一套文件。

1. **方向分支留原证据与上下文：**固定输入/结果/审结提交，主张—证据—适用边界，原始协议/数字/完整与未开始对象，专用实现及费用未知项。封存运行入口，保留已成立部分和负结果；不因关闭删除产物，不把本地大文件当作已被 Git 远程备份。
2. **master 收可独立引用的经验与基础：**提炼必要条件、强对照、测量/工程/资源教训及来源索引。代码只有确有通用需求、依赖与验证范围清楚时才接纳；不要为归档先做无需要的重构。完整矩阵、特定参考、历史 READY 与余额默认不搬入主线。
3. **逐项写清：**资产；来源提交/路径/对象；已经验证什么；不能继承什么；留分支/接纳 master/待接纳及原因；实际接纳提交。关闭的范围要区分固定候选、方法族和论文主线，不能用同一个 FAIL 代替。
4. **接纳必须落地或诚实标待办：**在已有作者授权与仓库约束内选择性接纳明确文件，核对差异及必要身份；已有授权不重复请示。未授权或未完成时写“待接纳”，不能把建议清单说成已合并。原分支不整支合入，也不自动推送；本地主线接纳和远端同步分别记录。
5. **保持轻量且可追溯：**更新复用索引/通用经验入口；本次接纳有独立凭证，不改写以前的接纳清单。封存数字保持原身份；文档/链接/Git blob 检查不能扩成重新跑实验。下一方向只读相关经验，按需追固定原文，不从头重扫所有旧失败。

本规则从 2026-10-21 的 B 关闭开始采用；A′ 的精炼经验可按既有复盘索引接纳，不追认过去没有做过的主线合并。示例见 RESEARCH_MASTER_PROMOTION_B_v1.md；科学角色和权限仍由本工作流统一定义。


### 交付与审查

```markdown
# 交付：<同一问题>
- 实现/结果提交；证据文件：
- 科学主张 / 测量有效性 / 工程状态 / 资源状态：
- 关键结果与分母；不确定性与缺项：
- 本轮增量与累计成本；完整/部分/未开始对象：
- 异议及更便宜的方案：
- Reviewer：继续 / 收窄 / 停止；理由；下一个会改变的决定。
```
