## 2. 传输协议及读前保护（拟实施合同）
以二进制有界通道代替文本Reader；各端仅使用显式固定byte[]/bytearray及带count的读写，不用ReadLine/ReadToEnd、无界队列或无界任务结果。下列为未来需源码落实及合成检验的约束。
stdout/stdin控制帧：4字节无符号小端长度头，加严格UTF-8负载；头、负载、换相确认都算通信。零长、超cap、溢出、非UTF-8、未知字段、重复键及越序帧拒绝。
**先限后分配**：读前预留4字节头及本次扫描/操作；头进入固定4字节缓冲，解析长度后先比较每帧、通道累计及阶段余额，再预留payload长度，最后只向既有缓冲读该长度。每次短读也计，EOF中断不申请剩余大缓冲。
接收额度按请求上界先扣，实际n字节另记；未读满的预留不释放成新风险额度。发送端同样在编码/写入前按固定schema的字节上界预留，不先任意json.dumps/异常str再测长度。
固定schema仅auth(40 ASCII)、run枚举、phase枚举、序号、状态码、4项计次及有界账户数值；最大64叶节点、深度4、字符串≤128 Unicode码点、整数0…2^63−1、无任意异常文本或向量。先核字段域，再用有界UTF-8编码器写固定TX缓冲，超限即拒绝。
UTF-8长度以传输字节为准；码点/UTF-16字符数仅为解码及对象图附加界，不能代字节cap；拒绝无效序列，不用替代字符改变身份。每帧≤16384负载B，严格解码后最多16384码点/32768 UTF-16 code units，schema另收紧字符串。
stdin启动路径最多4096 UTF-8 B、授权grant最多256 B，均已含在各自schema域；启动器在加载worker源码前完成固定头/缓冲/限额守卫，不再用`readline(16385)`作字节界。
stdout每worker仅seal_request和done各1帧（各≤16384）；stdin仅bootstrap和S_grant各1帧；无ACK后无限重发。第三帧只能读固定1字节探针即拒绝，探针预留并收费。
stderr作为独立原始字节通道，不解码拼接；每个V或S通道累计≤4096 B、固定256 B块，满额后仅允许1 B超额探针，非空即拒绝/终止；无ReadToEnd、traceback缓存或str(exc)展开。
应用拒绝只发固定错误码（不含载荷/路径长文本），仍受stderr额度；解释器/原生错误即使不遵循schema，也只能进入上述固定块和累计界，超额保留前4096 B及拒绝码，不再读剩余输出。
stdout payload累计≤32768 B+8头+探针；stdin≤4352 B+8头+探针；两阶段stderr共≤8192 B+2探针；按每个阶段/方向逐项派生实际占额，绝不沿旧8192假定。
任一端单向通道累计硬限仍≤2 MiB；上述更小协议界先触发。管道OS内部缓冲的大小、创建参数及是否可控必须在锁定平台核定，未核定不以默认值充界，计入树内存及未证项。

## 3. 环境、循环、寿命与退出
创建子进程前清空继承环境，只放白名单授权/路径/run及必要系统键，键数≤16、键≤64 ASCII、值≤4096 UTF-8 B；总编码环境块（含分隔符/终止符）≤16384 UTF-8 B，同时校验Windows UTF-16块上限32768 B。
以有限字段形成boot，禁止把整账本/旧包塞环境；每值在构造前有字符域上界，逐字段有界编码后核累计，再调用启动API。argv、工作目录、路径规范化、源码读取与环境复制分别预留双端成本。
固定读/写任务数量，不每次轮询新建异步任务；每通道最多1个pending read，缓冲活到该读完成/取消并回收后才复用。非阻塞完成检查不创建无限日志；所有通道并发有界排空，避免stderr堵住stdout握手。
最坏每字节1次短读，因此读调用数≤已预留字节数+每通道一次EOF/探针；每通道固定250 ms超时、每阶段轮询≤120000次（尚需锁定时钟/调度实现核定），到次数或绝对deadline先到即停，不能因短读重置阶段deadline。
UTF-8扫描≤4遍、头解析≤4步、payload复制≤4遍；有界JSON最多64节点/深度4，schema不允许长数值转大整数。异常路径、零字节读、超额帧、取消及合账也包含在操作预留中。
拟定两端每端同时RX/TX各16388 B、stderr块256 B、头/探针≤32 B；两端原始传输缓冲合计≤131680 B，另有环境、解析对象及封存缓冲，不能只报传输数组当总代理。
对象/字符串/编码器/任务/管道原生缓冲具体分配上界待锁定Python 3.12.8、PowerShell/.NET build及源码/原始API文档核定；旧环境仅锁Python/NumPy，不证明当前.NET行为。辅助候选风险占额1 MiB不冒充已证分配上界，未闭合不启动。
Windows继承Job树2 GiB、CPU代理512 MiB、CUDA0不变；全部准备、V、S、退出均留在Job内，外部监控含owner与worker。不得通过杀掉监控或离开Job换相。
拒绝时停止新payload读取/分配及科学动作，关闭写端、取消有界pending I/O，在已预留退出期限内等待，否则终止Job；失败封存仅由仍有独立S余额的owner完成。硬限/保护实际失效按ROLE停止，不能临时再启动独封。
Job终止后不能假定owner有机会写完整账；应由启动前已存在且本身有预算的监督者持有限失败槽。监督者/IPC/文件/退出成本必须进周期图，无监督者资格则只接受部分封存并交审，不承诺完整恢复。

## 4. V→S消息归属、双端合账与快照
计量单位为(endpoint, phase, channel, seq, direction)；owner/worker各自只追加，分别记录预留上界和观察字节n，合账作键去重求和，不能赋值覆盖另一端。发送write与对端read为两次逻辑I/O，二者都计。
grant必须确认接收端已有对应阶段读/写/退出完整预留；无法取得grant时不得发阶段payload。接收端在读前独立预扣，发送端预扣不能代替接收端。多扣V也不能证明S已计。

|消息/动作|owner归属|worker归属|快照/边界|
|---|---|---|---|
|环境、进程启动、bootstrap|V写/引导成本|V读/解析/源码引导|V预算预装后创建，启动失败仍V+预留S拒绝|
|seal_request|V读|V写|worker停止V科学动作，先关闭V stderr写端，最后发本请求|
|V stderr排空/EOF|V读|V写与关闭|owner核V pending完成、请求消费及EOF后冻结双方V观察值|
|S_grant|S写|S读|owner先验证S自身及worker余额并切绝对时钟，再发；worker读前已有S接收预留|
|封存/回读/清单|S自己的实际动作|S自己的实际动作|双端分立，文件回读与pipe均入S|
|done|S读|S写|worker快照为发送前观察值+发送/退出预留；不伪称最终全程实耗|
|退出/owner terminal|S读写/等待/监督尾耗|S退出|owner收到done后追加自身done读取、EOF、等待及terminal动作，不覆盖worker快照|

为消除排队stderr跨相歧义，拟预建V/S两套有界错误管道；V写端全关并观察EOF才发grant，worker切到S原生/解释器stderr后才能继续S。重复继承句柄及native fd重定向必须源码证明并合成核验，否则换相资格FAIL，不能按接收时钟猜归属。
stdout/stdin只允许上表注册帧顺序，无V后续帧；按帧类型及双端屏障共同归属，不能按函数返回时间任意挪账。环境归V且不跨相复用为新消息。
worker V快照应包含seal_request的预扣/发送观察；owner V截止包含其读取及V stderr EOF；S快照有各自序号、已结算观察与未完预留，只有成对身份/长度一致才合并通信观察。
done不可递归包含自己的最终编码长度：使用固定schema上界先预留，写后本端登记观察，owner据收到的真实帧长度建立对应项；若写后日志未能交付，观察保持部分，预算上界仍完整。
terminal同理采用先冻结完整序列化/写入/回读/退出包络，再落盘；“截至T观察”与“覆盖剩余的不可退款预留”分列。精确全程尾耗仍可null，资格依据完整可核前置上界，不伪造精确实耗。
合账不改旧ledger；新周期以独立授权和可核前驱安装账户，只引用旧账身份与占额一次。旧B保护失效、新结果后禁止复跑的事实不会被新合成PASS消除。
